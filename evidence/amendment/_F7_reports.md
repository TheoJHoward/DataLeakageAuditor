## 1. WHAT IT LICENSES — the criterion moves HARDER, and the hardening is far wider than the stated reason

**Lead attack: the replacement converts criterion 3 from an existential one-bit test into a universal exact-match test against an 888-cell key, and every one of the three new failure modes runs in the direction of not stopping the project.**

"Fires" is existential: one finding, anywhere on the contaminated side, at any tier, satisfies it. "Match … on **every** fixture side" is universal, and SC-3(b) supplies what non-match means:

> "**A finding the map predicts is REQUIRED.** Its absence is a miss."
> "**A finding the map excludes is a FALSE POSITIVE.** It fails the gate — on any side, at any tier, primary or secondary."

Against the actual key. The declaration's §13(a) records the map as `n1\declared_map.csv`, cell key "(`side`, `instrument`, `month`, `class`)", "**984 rows** = **960 declared-class cells** … Of the 960: **888 `SCORED`**", with the contaminated side saturated on every instrument-month. So the replacement requires a rival to (a) produce a required finding on every one of several hundred REQUIRED cells — one miss and criterion 3 fails — and (b) emit nothing on any excluded cell, **including on the contaminated side**, where the registered criterion imposed no false-positive constraint at all.

Three deltas, and their beneficiaries:

| | registered | replacement | who benefits |
|---|---|---|---|
| contaminated side, recall | one firing suffices | every REQUIRED cell, no misses | **author** (kill gate much harder to trip) |
| contaminated side, precision | unconstrained | any excluded-cell finding fails the gate | **author** |
| corrected side, real violations | firing there disqualified the rival | firing there is now required where the map declares one | rival (kill fires more readily) |

Net: **substantially HARDER — the project stops less readily.** Only the third row loosens, and it is narrow: the declaration records the corrected side non-zero in "**18 of the 48 instrument-months**". The first two rows apply across all 48 on both sides.

**Is the direction defensible?** The stated reason is, and it is candidly stated — the hunk's "Why" says a rival "could satisfy the kill gate by exhibiting exactly the behaviour the acceptance gate now scores as a miss", i.e. a rival that is silent everywhere on a characterized corrected side should not earn the project's surrender. That is correct on the merits and it is a tightening argument, openly made.

**The drafting is not defensible as scoped to that reason.** The retirement rationale is that §10.1 "is a second copy of the premise §6.2's criterion 3 retires — that silence on the corrected side is correct behaviour". Removing a second copy of a retired premise licenses editing the *corrected-side limb*. It does not license replacing the *contaminated-side limb* — which was never a copy of line 461, which the retired premise never touched, and which the hunk's "Why" never mentions. The minimal correction consistent with the stated reason is to keep "Fires on `fixture_contaminated`" and replace only "is silent on `fixture_corrected`" with a map-conditioned corrected-side test. What was written instead swallows the contaminated limb whole and adds a false-positive gate that no registered version of criterion 3 ever carried. The two undisclosed tightenings are the ones that decide whether the project stops.

Note the asymmetry the same words produce. §6.2's criterion 3 (SC-3) grades the author's own tool against this map, so the text looks even-handed. But the map, the cell key, the class set, the scored population and the fixture are all authored by the same person who authors the tool being spared; a rival is a fixed foreign artifact that must independently reproduce an 888-cell timing measurement. The registered predicate "Fires on `fixture_contaminated`" was agnostic to detector kind; a static-only rival with no runtime path now produces no runtime findings, cannot populate a single REQUIRED cell, and fails criterion 3 automatically. That is a further narrowing in the author's favour, unremarked in the hunk.

The replacement closes it. But §9.2's abstention rules now collide with SC-3(b): an abstention is an absence, and "Its absence is a miss." §10.1 criterion 3 as replaced cites no §9.2 protection, so on the plain words an ineligible or crashing rival scores misses rather than abstentions — a fourth tightening, and again unremarked.

## 2. CAN A RIVAL SATISFY CRITERION 3 WITHOUT THE AUTHOR RUNNING IT AGAINST THE MAP?

No — and that is the problem, not the reassurance. There is no self-certification route and no route that does not pass through an object only the author holds.

- **The comparison object is now internal.** The map is "declared in the fixture's availability declaration", indexed by a key "**the declaration declares**", over a scored population "**the declaration declares**" (SC-3(a), (c)). Nothing about a rival tool's own outputs can satisfy criterion 3; only an author-run comparison can.
- **Unevaluability is a live state, and it resolves against stopping.** SC-3(h): the map "is **declared and frozen before any detector runs** (SC-8)"; SC-8(a) freezes "at the moment the tag is signed" of "the amended registration". The kill gate is Phase 0 (§10.0 / the phase table, Phase 0 gate = "**Kill gate (§10.1)**"), and §6.2 fixes only that "**Reconstruction happens in Phase 0, before the cross-tool comparison** (§9.2)" — reconstruction of the *declaration*, with no clause anywhere requiring the *map* to exist, be frozen, or be published before the cross-tool comparison runs. Where the map is absent or unfrozen at comparison time, criterion 3 is neither satisfied nor refuted, and §10.1's own fallback disposes of it: "**Partial satisfaction is recorded and does not trigger the stop.**" An unevaluable criterion 3 is therefore a permanent no-stop. The registered criterion had no object it could be missing; it needed the fixture and the tool's output and nothing else.
- **On the ambiguity branch it is worse than unevaluable** — see §4.

So the answer to the question as posed: a rival can never be *established* as satisfying criterion 3 by anyone but the author, and where the map is missing it cannot be established at all. Both failure modes point one way.
