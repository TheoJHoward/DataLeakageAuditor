# `evidence/amendment/` — the rulings that define this amendment's FORM

Added at R73/§51. **Before this, these files existed only in a transient session scratchpad under
`AppData\Local\Temp\`** — so the rulings that decide *what the v30a amendment is* shipped outside
the signed object, while every document they govern shipped inside it.

| file | what it carries |
|---|---|
| `K1_SCHEMA_CLAUSES.md` | **R24**: *"`PREREG.md` gains the SCHEMA… the declaration keeps the DATA"*, and the drafted SC- clauses with each one's rule/instance justification |
| `DECLARATION_SCRUB_LIST.md` | **R20**: *"the declaration is not a normative annex"* — and the 138-row list, 40 rows named, of rules stated normatively in the declaration for which **no `PREREG.md` clause exists to carry them** |
| `SCHEMA_SET_FINAL.md` | the **source of record** for the applied clause text: SC-1 … SC-13c as corrected through R32, the three drafted insertions, and Q4's three defects |

**Why they ship.** A reader who has the tag can check what the registration says. Without these they
cannot check *what kind of change it was*, *why each clause is a rule rather than an instance*, or
*which normative rules had no home before it*. R20's own text names the risk this closes: a rule
stated only in the declaration is, after the amendment, *"stated normatively **nowhere**"*.

**Status.** Working records of the amendment's drafting, not normative text. `PREREG.md` remains the
sole normative source (`PREREG.md` §0.1). These are cited by the ceremony record and are frozen at
the tag by the commit, like every other file in this tree.
