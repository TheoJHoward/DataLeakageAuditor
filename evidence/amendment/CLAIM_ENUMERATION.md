# CLAIM ENUMERATION — what the signed object asserts

**What this is (§101.1).** The first list of the NUMBERS AND FACTUAL CLAIMS carried by the
registration's own surfaces, with the producer of each named. Built backward from the claims
(§93.2), not forward from the scripts — the forward search was the wrong shape and returned 59
scripts to audit; this returns the claims themselves.

**Population (§30.1).** Three surfaces, exactly as §93.2 names them: the six-file set, the tag
message body, and the §12 disclosures (`R69_DISCLOSURE_LINES.md`, `LARGE_ARTIFACTS_RECORD.md`).

**Exclusion, stated with the result (§30.1).** Rule text is out of population **by design**:
`§6.2`, `criterion 3`, `item 8`, `L2a` are identifiers and thresholds a specification FIXES, not
measurements it REPORTS. A threshold has no producer to audit, and including them would bury the
claims that do have one. **This is an exclusion by kind, justified here, not a silent filter.**

## THE INSTRUMENT'S OWN LIMITS (H-L21 — a PASS is a statement about a domain)

**These counts are a FLOOR, not an extent.** Two limits, both load-bearing:

1. **The producer classifier reads a ±1-line window.** `NONE` therefore means *no artifact was
   cited within one line of the figure* — **not** *the figure has no producer*. The true SCRIPT
   count is higher than the one below.
2. **`HAND 0` is an instrument artifact and is reported as one.** Hand counts certainly exist in
   this corpus; none matched the pattern. A zero that the instrument cannot distinguish from
   "absent" is not evidence of absence — that is B5.3 restated, and it applies to this table.
